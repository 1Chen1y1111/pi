# Pi 业务逻辑可视化说明文档

本文档集面向不懂技术的产品经理、设计、运营和业务同学。它不要求读者理解源码，而是把 Pi 这个终端 coding agent 拆成“用户、任务、工具、会话、模型、扩展、界面”几条业务主线，用 Mermaid 图表说明业务如何流转。

## 你应该重点挖掘什么

Pi 表面上是一个命令行工具，但业务上更像一个“可持续工作的开发助手平台”。值得深入挖掘的点有 7 类：

```mermaid
mindmap
  root((Pi 业务挖掘点))
    用户旅程
      首次启动
      登录认证
      发起任务
      中途纠偏
      恢复历史
    任务执行
      模型理解需求
      工具读写项目
      循环推进
      输出结果
    工具协作
      读文件
      改文件
      跑命令
      搜索定位
    会话资产
      自动保存
      分支探索
      历史压缩
      导出分享
    模型供给
      Provider
      OAuth
      API Key
      Thinking Level

      Skills

      Themes
      Packages
    终端体验
      TUI
      快捷键
      消息队列
      工具结果可视化
```

## 一句话理解 Pi

```mermaid
flowchart LR
  U["用户提出开发任务"] --> P["Pi 理解任务"]
  P --> M["选择模型"]
  M --> T["调用读写/命令/搜索工具"]
  T --> R["把结果反馈给模型"]
  R --> D{"任务完成了吗"}
  D -- "否" --> T
  D -- "是" --> O["给用户输出结果并保存会话"]
```

Pi 的核心价值不是“回答问题”，而是“在真实项目目录中持续行动，并把过程沉淀成可恢复、可分支、可扩展的工作会话”。
